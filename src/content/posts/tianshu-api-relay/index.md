我同时用 Claude 写代码、用 GPT 处理长文档、用 Gemini 的图像模型出图，偶尔还要拉 Grok 写点东西。

一年前，这套组合意味着：一张外币卡、三个平台的账号、三个计费后台、三套 SDK、三份随时可能失效的 key。**切一个模型要改一次环境变量和依赖。**

现在这些全收在一个 `base_url` 后面。

这篇文章写我怎么挑中转站、现在在用哪家、以及哪些场景**不该**用。文末有注册入口，我如实说明：那是推广链接。

## 先说清楚中转站到底是什么

它不是「更聪明的模型」，本质是一个**协议网关**：

```
你的代码 → 统一的 OpenAI 兼容接口 → 网关按分组路由 → 真实的模型
```

对调用方来说只有一个变化：把 `base_url` 从 `https://api.openai.com/v1` 换成中转站的地址，`api_key` 换成站里发的那串 `sk-`。代码一行不用改。

> [!NOTE]
> 正因为只是换地址，**任何支持自定义 base_url 的客户端都能接** —— 包括酒馆（SillyTavern）、Cherry Studio、各种 AI IDE、以及 `openai` 这个 Python 库本身。

## 我挑站的四条标准

用了一年中转站，踩过跑路、踩过分组降智、踩过 key 被静默切组，标准最后收敛成四条：

**一、协议兼容度够不够。** 只支持 OpenAI 协议的站，接不了 Claude Code 和 Gemini CLI —— 这两个工具要的是原生协议头。挑站时先确认它认 `x-api-key` 和 `x-goog-api-key`。

**二、计价透不透明。** 分组公开、倍率公开，你才能算清楚钱花在哪。那种只有一个模糊「1 元 = X 万 token」的站，出了问题和跑路之间没有中间状态。

**三、有没有实时成功率。** 这是**唯一**能提前告诉你「这个分组今天能不能用」的指标。中转站的分组是动态的：上游账号被封、被限流、被降智，表现就是成功率断崖。看不到这个数字，你只能在报错之后才知道。

**四、充值门槛和退款。** 第一次只充最小额度，跑满一周再决定要不要加钱。这条能过滤掉九成不靠谱的站。

## 我现在用的这家：天枢 API

站点自我描述是「**多模型 AI API 中转站**」，接口地址 `https://tianshuapi.top`。

有意思的是它把自己的底牌摊得很开——我扒了一下它的公开模型广场，是一个不用登录就能查的 JSON 接口：

```
GET https://tianshuapi.top/api/v1/model-plaza
```

> [!WARNING]
> 表里的成功率是**我写这篇文章那一刻**抓的，它会随上游状态浮动，不要当成长期承诺。把它当成一个「现场读数」看，这才是它的正确用法。

平台支持面也确认过：请求 `/v1/models` 不带 key，会返回

```json
{"code":"API_KEY_REQUIRED","message":"API key is required in Authorization header (Bearer scheme), x-api-key header, or x-goog-api-key header"}
```

三种头都认，说明 **OpenAI / Claude / Gemini 三套客户端可以直连同一个站点**。另外它开了 MCP 支持。

## 一条重要的反直觉结论

**倍率低 ≠ 便宜好用。**

上面那张表里，`0.06` 那组成功率 80.5%，`0.40` 的 Gemini 组只有 55.9%。如果按单价排序去选，你会精准踩中最不稳的那两档——而一次失败的请求，浪费的不只是钱，还有你等它返回的那十几秒。

正确的顺序是反过来的：**先看成功率筛掉不稳的，再在剩下里挑便宜的。**

> [!TIP]
> 具体做法：每个候选分组充最小额度，连着跑三天，用真实成功率决定主力放哪一组。我现在的分工是「国模渠道跑日常批处理 + Claude 满血跑代码 + 便宜组跑草稿」，成本比全用官方便宜一大截，稳定性也够。

## 接入只有三步

1. **注册**：邮箱即可，站里没设邀请码门槛（我注册时是这样）
2. **建 key**：后台生成一串 `sk-` 开头的密钥
3. **改 base_url**：本地环境变量换成站里的地址

```bash
# 环境变量方式，适合大多数客户端
export OPENAI_BASE_URL="https://tianshuapi.top/v1"
export OPENAI_API_KEY="sk-你的密钥"
```

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://tianshuapi.top/v1",
    api_key="sk-你的密钥",
)

resp = client.chat.completions.create(
    model="gpt-6.1-sol",
    messages=[{"role": "user", "content": "说一句话证明你在工作"}],
)
print(resp.choices[0].message.content)
```

酒馆这类 GUI 客户端不用写代码，填两栏就行 —— 这个坑我在[上一篇](https://du-19.top/posts/grok-tavern-debug/)里详细写过。

## 我在这家踩过的三个坑

老实说，不是一路顺利。我之前那篇排障文里记了三件事，现在看依然成立：

1. **探针脚本被拉黑**：Python 的 `urllib` 默认 UA 是 `Python-urllib/3.13`，网关直接拒。换个正常 UA 就通了。这不是站的问题，是我脚本的问题。
2. **连续 413 误判成体积超限**：真相是那个分组当天上游在排队，网关把排队超时包装成了 413。
3. **key 被静默切到别的分组**：后台改分组不会通知客户端，表现是「同一个模型突然变笨」。改完分组务必重新验证一次输出质量。

另外提醒一句：我之前文章里写的 `lingzhanai.top` 是**旧地址**，现在已经 301 跳到 `tianshuapi.top`。照着旧配置抄的人，反向代理 URL 记得一起改，否则会连到一堆看不懂的报错上。

## 什么情况下别用中转站

这条比前面所有内容都重要：

- **公司数据、客户隐私、涉密内容** —— 不要走中转。它的链路是「你 → 第三方网关 → 上游」，多了一跳就多一个信任假设，而这一跳你审计不了。
- **需要 SLA、发票、合规背书** —— 走官方。中转站给不了这些。
- **长期高频且模型固定** —— 算完账你会发现官方直采往往更稳，价格差距没想象中大。

它真正的价值是：**低成本试错**。想验证一个模型值不值得上、想给学生党省点钱、想同时跑几家做效果对比 —— 这些场景它没有对手。等你的用量稳定下来，该迁官方就迁官方，这不冲突。
