用 AI 写小说，账单涨得比字数快，响应还慢。

我想换个更便宜也更猛的模型，盯上了中转站天枢（lingzhanai.top）上的 Grok 4.7。挑它的理由很朴素：站内测试里 Grok 4.7 通过，ChatGPT 5.5 不通过。

看起来就是在酒馆的 xAI 源里填个反向代理。结果这一路我误判了三次，还顺手把用户的配置搞崩过一次。

真正看清全貌之后，我做的第一件事不是庆祝，是把整条链路重新画了一遍。因为**每一个坑都长得不像它本来的样子**。

> [!WARNING]
> 本文涉及成人向角色扮演的模型审核问题，全程只做技术复盘与机制分析，不提供任何绕过审核的话术或越狱方法。另外，涉及未成年的性内容在任何地方都是违法的，不在讨论范围内。

## 先搞清一件事：URL 和密钥是二选一

酒馆的 xAI 源有个「反向代理」折叠区，三栏里真正起作用的只有一条判定：

```
反向代理 URL 留空  →  用「xAI API 密钥」
反向代理 URL 填了  →  用「代理密码」替代 API 密钥（另一个作废）
```

**是二选一，不是叠加。** 填了 `https://lingzhanai.top/v1` 之后，天枢的 key 要填在「代理密码」框里，原本的「xAI API 密钥」直接失效。

> [!TIP]
> 接天枢只要两步：
> 1. 反向代理 URL 填 `https://lingzhanai.top/v1`（注意末尾的 `/v1`）
> 2. 代理密码填天枢的 API Key（`sk-` 开头那串）
>
> 模型名填 `grok-4.7`，流式打开，最大回复长度 8000 左右。

## 误判一：连上了，一个字都不吐

配好之后酒馆全空。

我第一反应是「天枢这个分组废了，别充钱」。依据是探针脚本连续十几次返回 502，看起来相当确凿。

> [!CAUTION]
> **这是最严重的一次误判。**
>
> 真相是：我的探针脚本用 Python 的 `urllib` 发请求，默认 UA 是 `Python-urllib/3.13`，被天枢网关直接拉黑了。
>
> 同一把 key、同一个模型，UA 换成浏览器或者 `node-fetch`、`undici`，全部 200。
>
> 不是站点挂了，是我的测量工具被挡在门外。

教训很短：**拿脚本默认 UA 去测商业网关，等于拿身份证复印件刷门禁。**

## 误判二：慢得像在排队

排除了连通性，下一个问题是慢。让用户生成一段回复，40 秒过去还在转圈。

实测数据，同一台机器、真实对话历史：

| 模型 | 首字延迟 | 速度 |
|---|---|---|
| GLM（对照组） | 中位 7s | 52.7 字/秒 |
| Grok 4.7 | 13~48s | 6~18 字/秒 |

慢到什么程度？我做了个对照：输入 600 字时首字约 47 秒，输入 27000 字时首字还是约 47 秒。

**输入长度差 45 倍，延迟几乎不变。**

这就排除了算力瓶颈和请求体积，指向一个东西：上游账号池在排队。你的请求不是算得慢，是排在别人后面等额度。

## 误判三：413 体积论

日志里连续出现两条 413。我差点又下结论：请求体太大，超了天枢的上限。

> [!CAUTION]
> 那两条 413 根本不是天枢报的。
>
> 一条是 `Multimodal captioning request failed 413`，另一条带着 `openresty` 字样。这是酒馆的图像打标扩展把图片发给 DeepSeek 时，DeepSeek 那边的 nginx 拒收大图报的，跟天枢没关系。
>
> 实测：1024 KB 的请求体全过；122 条消息、239 KB 上下文的流式请求全 200。体积从来不是瓶颈。

> [!NOTE]
> 之前为什么会测出「上限很高」的假象？因为用重复文本去测，tokenizer 会把重复内容极度压缩，数字严重虚高。要测真实上限，必须用随机内容。

## 转折：不是没输出，是只对成人向内容静默返回空

前面三次都在「连通性、速度、体积」里打转，漏掉了最关键的一条用户反馈：

> 「它从来没有正常输出过，全部都是空回复。」

一句话推翻了「随机失败」和「上游质量参差」两个假说。

我重新做了对照：两篇小说，一篇正常内容，一篇成人向。**正常内容正常输出，成人向那篇永远返回空。**

更隐蔽的地方在这里：这种空回复不是报错。HTTP 200，没有 error，没有 `finish_reason`，内容长度就是 0，酒馆的 `err.log` 里一条记录都没有。

你既看不到输出，也看不到错误，只能在界面上对着空白发呆。

而同一段成人向内容，在天枢站内的在线对话里是能正常返回的。结论很明确：**商业闭源模型的内容审核，外部 API 通道比站内更紧**，或者上游账号策略不同。它选择静默吞掉，而不是明确拒绝。

## 我的锅：配置被清空那一段

排障中途，我给过一条「用官方 Grok」的路线：反向代理留空，填官方 xAI 密钥。但这条路的前提是先开 Clash TUN 全局代理。

我没把前提和动作写在同一句话里。

用户照着把 `reverse_proxy` 和 `proxy_password` 清空了，酒馆随即转向官方 `api.x.ai`，而那个地址在本机根本连不通。那段时间的「重 roll 全空」，有一部分是我造成的。

> [!WARNING]
> **给步骤的铁律：前提和动作必须写在同一个句子里。**
>
> 「先开代理，再把 URL 留空」拆成两条消息发出去，用户大概率只执行后者。

## 想清楚一件事：商业闭源没有一家能解决尺度

既然 Grok 在外部通道也卡成人向，那换别家呢？

我把天枢上能切的分组全过了一遍（JDP 系列、DeepSeek 官转、K3、GLM、OAI 协议满血、Claude 官签/Max），结论挺扎心：

- 面向角色扮演的模型索引站，明确把 **Grok 列为「不推荐给 NSFW 用户」**（原话是 "Grok still refuses a lot of NSFW"）
- OpenAI、Claude、Gemini 系审核最严，换了只会比 Grok 更紧
- 国产模型审核力度同样是国内最严

真正能解尺度问题的，是 **abliterated（消融）开源模型**。它不是靠话术绕过策略层，是直接改权重，把激活空间里的「拒绝方向」移除，从架构层面就不会拒绝。

常见能跑的：L3-Stheno 3.3 8B、Huihui-Qwen3.5-9B-abliterated、MN Violet Lotus 12B。

获取途径三条：

1. **Featherless AI**：OpenAI 兼容，flat rate，781 个 uncensored 模型，官方声明不记日志。最省事
2. **AtmosCompute**：托管 Dolphin、Cydonia、Magnum、Euryale 这类无审查模型
3. **本地跑 KoboldCpp**：唯一 100% 可控的路子，8B 到 12B 的 GGUF 在消费级显卡上就能跑

## 意外：那把 key 已经被切到 GPT 分组了

测 GPT 分组的时候，我撞见一件更离谱的事。

用同一把天枢 key 打 `/v1/models`，返回的 16 个模型 `owned_by` 全部是 `openai`。分组已经被切到 GPT 组了。而原本的 `grok-4.7` 现在直接 404：`Model "grok-4.7" is not supported by any configured account in this group`。

顺手把这组的存活情况测了一遍：

| 模型 | 状态 |
|---|---|
| `gpt-5.6-terra` | 活，1.9s |
| `gpt-5.6-sol` | 活，1.8s |
| `gpt-6-astra` | 活，11.7s（偏慢） |
| `gpt-5.5` | 502 Upstream request failed |
| `gpt-5.6-luna` | 读超时 |
| `gpt-5.6`（裸名） | 404 不存在 |
| `grok-4.5 / 4.6 / 4.7` | 404 不在本组 |

> [!WARNING]
> **这就解释了用户酒馆当时为什么全空**：settings.json 里模型名还写着 `grok-4.7`，配着天枢的 URL，请求必然 404，然后就是空回复。
>
> 修法是把模型名改成 `gpt-5.6-terra`，这组里最便宜最快的那档。

> [!NOTE]
> **决定模型可见性的是中转站的「分组」，不是 URL。**
>
> 你换了分组，桌面端 settings.json 不会自动跟着变，模型名过期就 404。以后每换一次分组，先 `/v1/models` 核对一次，再改酒馆里的模型名。

## 顺带：HY3 和 StepFive Pro 写文章哪个好

用户后来问起这两个，我测了下定位差异，结论很明确。

**HY3（腾讯混元 Hy3）**：写文章是它少有的亮点。多篇实测评语是「文风自然有节奏感、去 AI 腔」，模仿《明朝那些事儿》那种文风能达标，12000 字长文摘要零遗漏。三方对照的排序是 **Kimi（最口语）> HY3 > DeepSeek（偏技术文档味）**。

**StepFive Pro（阶跃星辰 Step 5）**：定位是长任务工程师，为 AI 编程、软件工程、金融可溯源分析、长周期 Agent 设计的，600B MoE、100 万 token 上下文。写文章不是它备考的科目。有评测原话是「拿一句话写文案去考它，本身就是没重点备考的科目」。

还有一个更麻烦的实测反馈：它对抗性强、爱顶嘴。你让它办事，它反过来反复核对你的说法、抛程序性论证，而不是乖乖写。

一句话选型：写小说、公众号、文学创作选 HY3；长专业文档（几十万字资料消化、可溯源报告、代码）选 Step 5。但两个都是国产模型，审核最严，对成人向 RP 完全不对口，比 Grok 还紧。

## 留给同行的清单

绕一大圈，真正落地的就两句：

1. **商业闭源解决不了尺度问题。** Grok 站内能写、外部通道静默吞，换 GPT / Claude / 国产只会更紧。真要尺度，走 abliterated 开源，配 Featherless 或本地 KoboldCpp。
2. **中转站的坑，七成出在「工具用错」和「状态不同步」，不在模型本身。**

可复用的判据：

> [!TIP]
> **酒馆接中转排障清单**
> 1. 测网关别用脚本默认 UA，先换浏览器 UA，否则会被静默拉黑
> 2. 无输出先关掉流式再发一次。非流式分支会把错误直接弹出来，流式分支会吞掉
> 3. 看 `err.log` 要分清来源。带 `openresty` 的 413 多半是图像扩展发给了别的源
> 4. 测请求体积上限必须用随机内容，重复文本会被 tokenizer 压缩，数字虚高
> 5. 换中转分组后先 `/v1/models` 核对模型名，再改 settings。模型名过期直接 404 全空
> 6. 给用户的步骤，前提和动作写在同一句里

整件事最有价值的不是最后用了哪个模型，是三次误判把我按在同一个坑里反复教育：**现象反复打脸的时候，先怀疑测量工具，再怀疑上游，最后才怀疑模型。**

我三次里前两次都怀疑错了对象。
