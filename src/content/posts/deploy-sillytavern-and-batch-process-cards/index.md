# 一、背景：为什么要本地跑一个酒馆

一直想在自己电脑上跑一个 AI 角色扮演前端，随时随地和角色对话，数据也留在本地。选型上 SillyTavern 是开源里最成熟的方案之一：纯网页、支持几乎所有主流和自建模型后端、角色卡生态庞大。

但真正动手之后发现，"跑起来"只是第一步。我手头攒了一批角色卡，混着英文卡、中文卡、还有一堆根本不是卡的图片，模型偶尔还会"想半天不说话"。于是这一篇把从部署到批量处理角色卡的全过程记下来，供后来人少踩坑。

# 二、部署：把酒馆跑成 Windows 服务

SillyTavern 官方给的是 `node server.js`，双击 `Run-Tavern.bat` 就能跑。但这有两个问题：一是每次开机要手动点，二是那个黑窗口一关，服务就断了。对于一个"想用就用"的本地服务，这显然不够。

正确做法是用 **NSSM（Non-Sucking Service Manager）** 把它包装成 Windows 服务：

```bash
nssm install SillyTavern "<node.exe 路径>" "server.js"
nssm set SillyTavern AppDirectory "C:\Users\你的用户名\SillyTavern"
nssm set SillyTavern Start SERVICE_AUTO_START
nssm set SillyTavern AppExit Default Restart
```

关键点有三个：

- **开机自启（SERVICE_AUTO_START）**：登录之前就起来了，不用手动点。
- **崩溃自动重启（AppExit Default Restart）**：进程异常退出会自动拉起。我实测过，强制杀掉进程后 15 秒内新进程就接管了 8000 端口，服务全程 Running。
- **无窗口（LocalSystem 账户）**：运行在系统会话里，没有可见控制台，再也不会被误关。

还有一个细节：SillyTavern 的 `config.yaml` 里有一项 `browserLaunch.enabled`，服务模式下开着毫无意义，只会凭空起一个看不见的浏览器进程，记得关掉。

# 三、角色卡的本质：PNG 里藏着的 JSON

要批量处理角色卡，先得理解它的存储格式。一张 `.png` 角色卡，表面上是个图片，实际上在 PNG 里塞了一个 `tEXt` 文本块，结构是：

```
keyword(关键字) \0 base64(JSON)
```

关键字叫 `chara`（V2 卡）或 `ccv3`（V3 卡），里面是角色的全部设定：姓名、性格、外貌、开场白、示例对话、系统提示、标签等等。图片像素数据照常存在 `IDAT` 块里，所以角色卡"既是图又是数据"，图标就是角色立绘。

> [!NOTE]
> 处理 PNG 时最容易被忽略的一步是 **CRC32 校验和**。每个 chunk 末尾都有 4 字节 CRC，重写 chunk 后必须用 `zlib.crc32(chunkType + chunkData)` 重新计算，否则图片会被判定损坏、酒馆读不出来。

正因为数据就在 PNG 里，我们才可以用 Python 脚本直接读写，不需要打开酒馆界面。**注意 PNG 里顶层和 `data` 子对象各存了一份设定字段，改的时候两层都要同步；V3 卡有 `ccv3` 块，也要一起重写。**

# 四、第一步：让英文卡也能用中文回复

我这批卡里大部分是英文卡，但我是中文用户，对话当然希望模型用中文回。最稳的办法不是逐张翻译正文，而是给每张卡加两条"输出语言约束"：

- **`system_prompt`**（前置规则）：明确要求"无论用户用什么语言输入，只输出简体中文"，并规定专有名词译法、拟声词写法。
- **`post_history_instructions`**（末尾强化）：放在上下文最末尾，权重最高，相当于最后再叮嘱一次"全程中文"。

一套脚本扫过整个目录，给一千多张卡全部注入这两条规则。处理逻辑有几条讲究：**原有作者的设定一律保留、新规则追加在后**；**幂等**，重复跑不会重复注入；**逐张重算 CRC 并校验**，正文一字不动。最终全量校验，一千多张卡 CRC 全部通过、规则全部到位。

这一步做完，"用英文卡也能聊中文"的问题就解决了——因为约束是语言层面的，不依赖正文是否被翻译。

# 五、第二步：正文翻译与合规过滤

接着做正文翻译。先扫描一遍全库，看清家底：一千多张卡，几百张中文、几十张中英混合，剩下都是英文，英文正文合计四百多万字符。

> [!WARNING]
> 四百多万字符没法一次对话吞下，必须分批。我会按目录切片，先挑一个目录做验收样本，确认翻译质量再往下推。

翻译遵循几条硬规矩：术语用通行译名、保留 `*动作描写*` 标记、保留 `{{char}}` / `{{user}}` 变量、保留 `<START>` 这类结构标记、拟声词中文化。

另外有一件事必须说清楚：**扫描时发现一批卡同时带有"未成年人年龄标记 + 性化内容"，这类内容我不会翻译**。我写了一个正则筛查脚本，把这类卡单独列进跳过清单，后续批次自动排除。合规红线不能碰，这是底线。

# 六、第三步：清理伪角色卡

目录里还混着二十多张"伪卡"——它们是普通的 AI 绘图作品，PNG 里只有图片本身，没有任何 `chara` / `ccv3` 角色数据（顶多有些绘图软件写入的标题、参数、XMP 元数据）。这些文件对酒馆毫无意义，就是噪音。

清理前先做只读核对：逐个解 PNG chunk，确认确实没有角色数据才列入待删清单，并附上每张的大小和元数据说明。删除走的是**回收站**而不是彻底抹除——虽然用户说直接删，但回收站可还原，等于留了退路。删除后再复核一遍：剩下的每一张都是有效角色卡，之前注入的中文规则 100% 保持，没有误伤。

# 七、第四步：DeepSeek 思考截断排障

部署和整理都顺了，聊天时又撞到新问题：模型"思考了一会"，然后输出一大段话说到一半就停了，正文几乎没出来。

根因是三个设置叠出来的：

| 设置 | 原值 | 问题 |
|---|---|---|
| 回复长度 `openai_max_tokens` | 800 | 思考模型光"思考"就吃掉几百 token，正文写到上限就被掐断 |
| 思考力度 `reasoning_effort` | auto | 对 DeepSeek 来说 auto 等于不传这个参数，模型按默认力度狂想 |
| 流式输出 `stream_openai` | 关 | 长思考时一直白屏等，容易整体超时 |

修法是把回复长度提到 2048、思考力度设为 `low`、打开流式输出。另外在角色卡末尾补了一条指令：直接以角色身份输出剧情与对白，**禁止把写作计划、思考过程写进回复**，避免它把策划腔当正文吐出来。

> [!CAUTION]
> 改完设置后**一定要刷新浏览器页面**。酒馆的设置是浏览器端持有的，旧标签页一旦再保存就会把改动覆盖回去，这点特别容易踩。

# 八、收尾

这一通折腾下来，收获不只是一台能开机自启、崩溃自愈的本地酒馆，还有一套可复用的脚本：扫描、注入规则、翻译回写、合规筛查、回收站清理，每一步都能独立跑、能续做。

最大的体会是：AI 工具链里最难的部分往往不是"接上模型"，而是把一堆零散的卡、模型参数、输出语言这些脏活累活用脚本自动化掉。一旦形成流水线，再多的卡也只是时间问题。

> [!TIP]
> 如果你也想本地折腾 SillyTavern：先把服务跑稳，再处理语言问题，最后才轮到正文翻译这种重活。排序错了，很容易在"模型不说话"的泥潭里浪费一整晚。
