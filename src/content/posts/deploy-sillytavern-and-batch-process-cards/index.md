装好酒馆的第一晚，我打开一张卡，用中文打招呼。

角色回了我一段英文。

我又发了句中文，它还是英文。换了三张卡，全都这样。翻了翻才发现，我这一千多张卡里大半是英文作者的，正文、示例对话全是英文，模型自然顺着英文往下说。

一千多张卡，一张张改是不可能的。这篇就是从「装个酒馆」到「批量收拾一千多张卡」的完整记录。

## 先解决一个更基础的问题：别让它随时会断

官方给的方式是 `node server.js`，或者双击 `Run-Tavern.bat`。能用，但有两个毛病：每次开机要手动点；那个黑窗口一关，服务就断了。

对一个「想用就用」的本地服务来说，这不合格。

正确做法是用 **NSSM**（Non-Sucking Service Manager）把它包装成 Windows 服务：

```bash
nssm install SillyTavern "<node.exe 路径>" "server.js"
nssm set SillyTavern AppDirectory "C:\Users\你的用户名\SillyTavern"
nssm set SillyTavern Start SERVICE_AUTO_START
nssm set SillyTavern AppExit Default Restart
```

三个关键点：

- **开机自启**（`SERVICE_AUTO_START`）：登录之前就起来了，不用手动点
- **崩溃自动重启**（`AppExit Default Restart`）：进程异常退出会被拉起。我实测过，强杀进程后 15 秒内新进程接管了 8000 端口，服务状态全程 Running
- **无窗口**（LocalSystem 账户）：跑在系统会话里，没有可见控制台，再也不会被误关

还有个细节。`config.yaml` 里有一项 `browserLaunch.enabled`，服务模式下开着毫无意义，只会凭空起一个你看不见的浏览器进程，记得关。

## 角色卡到底是什么：一张藏着 JSON 的 PNG

想批量处理，得先知道东西存在哪。

一张 `.png` 角色卡，表面是张图片，实际上 PNG 里塞了一个 `tEXt` 文本块，结构是：

```
keyword(关键字) \0 base64(JSON)
```

关键字叫 `chara`（V2 卡）或 `ccv3`（V3 卡），里面是角色的全部设定：姓名、性格、外貌、开场白、示例对话、系统提示、标签。像素数据照常存在 `IDAT` 块里，所以角色卡既是图又是数据，图标就是角色立绘。

> [!NOTE]
> 处理 PNG 最容易被忽略的是 **CRC32 校验和**。每个 chunk 末尾有 4 字节 CRC，重写 chunk 之后必须用 `zlib.crc32(chunkType + chunkData)` 重新算一遍，否则图片会被判定损坏，酒馆直接读不出来。

数据既然就在 PNG 里，就能用 Python 直接读写，不用开酒馆界面。

这里有个坑我踩过：**PNG 顶层和 `data` 子对象各存了一份设定字段，改的时候两层都要同步**。V3 卡还有 `ccv3` 块，也得一起重写。只改一层的结果是「改完就还原」，你会以为是脚本的问题，其实是数据有两份。

## 第一步：不翻译正文，也能让英文卡说中文

最稳的办法不是逐张翻正文，而是给每张卡加两条输出语言约束：

- **`system_prompt`**（前置规则）：明确要求「无论用户用什么语言输入，只输出简体中文」，并规定专有名词译法、拟声词写法
- **`post_history_instructions`**（末尾强化）：放在上下文最末尾，权重最高，等于最后再叮嘱一次

一套脚本扫过整个目录，一千多张卡全部注入这两条。几个讲究：

- 原有作者的设定一律保留，新规则追加在后，不覆盖
- 脚本幂等，重复跑不会重复注入
- 逐张重算 CRC 并校验，正文一个字不动
- 最后全量校验，一千多张全部通过，规则全部到位

这一步做完，「英文卡也能聊中文」就解决了。因为约束在语言层面，不依赖正文有没有被翻译。

## 第二步：翻译正文，顺便撞见不该碰的东西

接着做正文翻译。先扫一遍全库看清家底：一千多张卡，几百张中文、几十张中英混合，剩下的英文，英文正文合计四百多万字符。

四百多万字符，没法一次吞下。按目录切片，先挑一个目录做验收样本，质量确认了再往下推。

翻译的硬规矩：术语用通行译名、保留 `*动作描写*` 标记、保留 `{{char}}` / `{{user}}` 变量、保留 `<START>` 这类结构标记、拟声词中文化。

另外有一件事必须说清楚。扫描时发现一批卡同时带有「未成年人年龄标记 + 性化内容」，这类我不翻译。写了个正则筛查脚本，把它们单独列进跳过清单，后续批次自动排除。这是底线，没有讨论空间。

## 第三步：清理伪卡

目录里还混着二十多张「伪卡」。它们是普通的 AI 绘图作品，PNG 里只有图片，没有任何 `chara` 或 `ccv3` 数据，顶多有绘图软件写入的标题、参数、XMP 元数据。

对酒馆来说这些就是噪音。

清理前先做只读核对：逐个解 PNG chunk，确认确实没有角色数据，才列入待删清单，并附上每张的大小和元数据说明。

删除走回收站，不走彻底抹除。虽然当时说的是直接删，但回收站可还原，等于留了条退路。删完再复核一遍：剩下的每一张都是有效角色卡，之前注入的中文规则 100% 保持，没有误伤。

## 第四步：模型「想半天不说话」

部署和整理都顺了，聊天又出新问题：模型思考了一会儿，然后吐出一大段话，说到一半停住，正文几乎没出来。

根因是三个设置叠在一起：

| 设置 | 原值 | 问题 |
|---|---|---|
| 回复长度 `openai_max_tokens` | 800 | 思考模型光思考就吃掉几百 token，正文写到上限被掐断 |
| 思考力度 `reasoning_effort` | auto | 对 DeepSeek 来说 auto 等于不传参数，模型按默认力度狂想 |
| 流式输出 `stream_openai` | 关 | 长思考时一直白屏等，容易整体超时 |

修法：回复长度提到 2048，思考力度设 `low`，打开流式。另外在角色卡末尾补一条指令，要求直接以角色身份输出剧情与对白，禁止把写作计划、思考过程写进回复，免得它把策划腔当正文吐出来。

> [!CAUTION]
> 改完设置**一定要刷新浏览器页面**。酒馆的设置是浏览器端持有的，旧标签页一旦再保存，就会把改动覆盖回去。这个坑我踩过不止一次。

## 收尾

这一通折腾下来，得到的是一台开机自启、崩溃自愈的本地酒馆，外加一套能复用的脚本：扫描、注入规则、翻译回写、合规筛查、回收站清理，每一步都能单独跑，也能接着上次的位置继续。

最大的感受不是「AI 真好用」，是**脏活累活必须脚本化**。一千张卡用界面点，是三个通宵；写成脚本，是半小时和一杯咖啡。

> [!TIP]
> 如果你也想本地折腾 SillyTavern，顺序别搞反：先把服务跑稳，再解决语言问题，最后才动正文翻译这种重活。
>
> 反过来的结果我试过，在「模型不说话」的泥潭里耗掉一整晚，最后发现只是服务没起来。
